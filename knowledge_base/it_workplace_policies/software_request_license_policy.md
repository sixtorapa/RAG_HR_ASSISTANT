# Software Request & License Policy

## 1. Why This Policy Exists

Unmanaged software installs create security risk and license compliance exposure. All software beyond the standard company build must go through this process, even if it's free.

## 2. Requesting New Software

Submit a request through the IT Request Portal with: tool name, business justification, and estimated number of users. IT Security reviews the tool's data handling practices before approval, particularly for any tool that would touch personal or customer data.

## 3. Approval Timeline

| Request Type | Typical Turnaround |
| --- | --- |
| Free tool, individual use, no sensitive data | 2-3 business days |
| Paid tool, individual use | 5 business days (requires budget approval) |
| Team-wide tool, any data sensitivity | 10 business days (Legal + IT Security review) |

## 4. Budget Ownership

Paid software is charged to the requesting team's budget unless it's a company-wide tool (e.g., the HRIS, the LMS), which is owned centrally by IT or People Ops. Renewals are reviewed annually for actual usage before automatic renewal.

## 5. Shadow IT

Using unapproved software for company work (e.g., a personal note-taking app syncing company data to a personal account) is a violation of the IT Security & Acceptable Use Policy, even if convenient — request it properly instead.

## 6. Browser Extensions

Browser extensions on company devices require the same approval process as other software, since many extensions have broad access to everything you view in the browser, including sensitive internal tools.

## 7. License Compliance

Do not share individual licenses across multiple people, and do not exceed the licensed user count for a team tool — IT periodically audits usage against license counts and will flag departments that need to true up.

## 8. Decommissioning

If your team stops using a tool, notify IT so the license can be reclaimed and reallocated rather than silently renewed each year.
